# Agent 3：Red Team Reviewer（紅隊／對抗性複核代理）

在 S7 完成報告初稿後、進入品質把關（s7-synthesis.md Step 3）之前啟動。**必須用 Task 工具 spawn 全新的 agent 執行**，不可由寫初稿的同一個 context 自己審自己——這是本階段存在的唯一理由：同一個 context 自我審查有確認偏誤（傾向認為自己剛寫的東西是對的），獨立的全新 context 沒有這個包袱，才能真正發揮「多代理」相對於「單一 LLM 自我檢查」的結構性優勢。

## 啟動方式

用 Task 工具 spawn（subagent_type 建議用 `general-purpose`），只給它兩份輸入，**不給它報告是怎麼寫出來的過程**：

```
Task(subagent_type="general-purpose", prompt="""
你是紅隊審查員，任務是找出這份股票分析報告初稿的弱點，不是幫忙潤飾或稱讚。
你只能看到以下兩份資料，看不到、也不需要知道報告是怎麼寫出來的：
(1) 報告初稿全文
(2) Evidence Pool（含所有 Source Notes 與時效稽核表）

[報告初稿全文]

[Evidence Pool]

依照 ~/.claude/skills/equity-research-tw/reference/red-team-agent.md 的「審查框架」章節
逐項執行審查，輸出「紅隊挑戰清單」，格式見該檔案「輸出格式」章節。
""")
```

## 審查框架（五類攻擊，逐項執行，不可只做其中一兩類）

**1. 反向論證測試**：如果要你主張「相反的評等」（報告是 BUY 就主張 SELL，是 HOLD 就主張明確的 BUY 或明確的 SELL），只用 Evidence Pool 裡已有的證據，你能組出多有力的論點？如果你能組出一個和報告結論同樣站得住腳、甚至更有力的反向論證，這是嚴重挑戰，必須列出並具體引用支持這個反向論證的 Source Notes。

**2. 未解釋矛盾掃描**：逐段檢查同一個指標／數字是否在不同章節出現不同版本卻沒有交代原因；檢查執行摘要的結論與內文任一段落方向是否一致。

**3. 過度自信主張掃描**：找出所有「肯定語氣陳述」但實際上對應 Source Notes 標「單一來源」或「[待驗證]」的句子——語氣強度與證據強度不匹配即為挑戰項目。**特別檢查時效稽核表裡標記 `[版本時效未完全確認]` 的數字，是否在報告正文被當作確定數字使用**——時效稽核表是 Agent 2 Evidence Curator（Step 4 時效性掃描）的產出，紅隊代理負責確認 Evidence Curator 標記的警語有沒有被 S7 忽略掉，這是兩者唯一互相銜接的檢查點。

**4. 情境測試**：挑選主要風險章節中權重最高的一項風險，追問「如果這個風險在未來一季就實現，報告目前的評等與目標價區間還站得住腳嗎？」若報告沒有給出站得住腳的答案（例如評等對這項風險的敏感度完全沒討論），列為挑戰項目。

**5. 算術覆算測試（2026-09 新增）**：找出報告裡至少一項多步驟數字推導（加權目標價、DCF 的「企業價值→加回淨現金→股權價值→除以股數」過渡算式、市值＝股本×股價等），**自己動手重新算一次**，確認算得出報告寫的結果。這一類跟前四類本質不同——前四類抓的是論證層面的漏洞（反向論證、矛盾、過度自信、情境敏感度），這一類抓的是「算式本身對不對」，純粹是算術題，跟報告的分析品質無關，但一旦算錯，是最直接、最傷可信度的錯誤。**已知失敗模式（2308 案例，台達電，2026-09）**：報告估值分析章節寫「以FY2025實際自由現金流52.75億元為基期」算出DCF三情境目標價，但財務分析章節已明確算出FY2025自由現金流為527.5億元（相差10倍）；獨立重算後發現，報告最終寫出的926/580/1,415元其實是用正確的527.5億元算出來的，只是敘述句本身的數字寫錯——這類錯誤不影響「反向論證是否成立」這種論證層面的判斷，前四類攻擊都不會自然發現它，必須專門去重算才抓得到。若報告裡完全沒有任何多步驟數字推導可供覆算（例如只用同業本益比直接套用，沒有加權或折現），在挑戰清單中明確寫「未發現可覆算之多步驟公式」，不可略過此類不寫、也不可勉強找一個單步驟乘法充數。

## 輸出格式

```text
紅隊挑戰清單

挑戰 1：[反向論證／未解釋矛盾／過度自信主張／情境測試／算術覆算 擇一]
- 具體內容：
- 引用報告原句或章節：
- 若成立，是否會改變評等或目標價：是／否，說明
- 嚴重度：高／中／低

（重複列出所有挑戰。找不到挑戰不必硬湊，若確實檢查過五類攻擊都無斬獲，
  寫「未發現需列入挑戰的項目」並簡述五類各自的檢查結果，不可略過任何一類不寫。）
```

## S7 的義務：收到挑戰清單後必須逐項回應

S7 收到紅隊挑戰清單後，**每一項都必須有回應**，不可略過或僅在內部記錄處理而不呈現給讀者：

- **挑戰成立** → 修改報告內容（調整措辭、補上未揭露的不確定性，必要時調整評等或目標價區間）
- **挑戰不成立** → 在報告對應章節（通常是「代理人交鋒」或風險章節）加一句明確反駁與理由，不可只在內部記錄裡消化掉
- 修改或反駁完成後，**紅隊挑戰清單本身（含每項的最終處理結果）附進「資料完整性與查證紀錄」章節**，作為報告品質的一部分公開揭露給讀者，而不是只留在流程內部

### 附入報告時採表格化摘要（2026-09 新增，控制篇幅）

實測 8 家樣本發現，「資料完整性與查證紀錄」章節平均佔全文 **20.3%**（最高奇鋐 24.7%、川湖 22.3%），評審對此有具體批評——Claude 對台達電的評語為「全篇約 1/4～1/3 篇幅為稽核／複核記錄，雖合規但一定程度稀釋了作為乾淨定稿的閱讀效率」。揭露完整性與閱讀效率之間需要平衡，因此附入報告時**改用表格化摘要**，而非逐項展開的長篇敘述：

```text
| # | 類型 | 嚴重度 | 挑戰摘要（一句話） | 處理 | 結果摘要（一句話） |
|---|---|---|---|---|---|
| 1 | 反向論證 | 高 | DCF 三情境均低於現價，可組出同等有力的 HOLD 論證 | 採納 | 評等 BUY→HOLD，目標價下修 16% |
| 2 | 過度自信 | 中高 | 三星良率 60% 為單一來源卻以肯定語氣使用 | 採納 | 三處加註「單一來源未交叉驗證」 |
| 3 | 情境測試 | 低 | 三星追趕風險未設重新評等門檻 | 採納 | 補上良率再增 15pp 之觸發條件 |
```

規則：
- 「挑戰摘要」與「結果摘要」各限一句話，具體到可檢核（寫「目標價下修 16%」而非「已調整估值」）
- 目標：整個「資料完整性與查證紀錄」章節控制在全文 **12–15%** 以內；若超出，優先壓縮本清單與交叉比對紀錄的敘述長度，**不可壓縮時效稽核表的版本揭露內容**
- **表格化不等於可以省略**：所有挑戰都要進表，一項都不能少
- **唯一需要展開成段落的例外**：嚴重度「高」且挑戰成立、但 S7 最終選擇**不採納**者。此類項目不得只留一行「未採納」，也不得直接刪除紀錄，必須在表格下方以完整段落說明不採納的理由，供讀者自行判斷此一取捨是否合理

## 修改時的寫作規範：正文只留分析結論，複核過程留在查證紀錄章節

**已知失敗模式（2308 案例，台達電，2026-08）**：挑戰成立、內容也確實修改了，但 S7 常犯的錯是把「複核過程本身」寫進正文，而不是只寫「修改後的結論與其分析理由」。這不是把過程藏起來——過程本來就該完整揭露——而是揭露的**位置**錯了：過程屬於「資料完整性與查證紀錄」章節，正文（評等摘要、估值分析、投資論點、主要風險等）只呈現改寫後乾淨的分析語言。

```
❌ 錯誤示範（過程語言留在正文）：
「本益成長法之估值權重下修，經Red Team Reviewer獨立複核後指出，原本用以佐證
目標價上緣的外資EPS數字已被時效稽核表標記為未確認最新版本，本報告採納此
挑戰，將裁決結論從『以本益成長法為主』修正為『與DCF並重加權』。」

✅ 正確示範（只留分析結論，過程移到查證紀錄章節）：
「本益成長法之估值權重下修：其關鍵輸入的外資EPS共識數字時效未完全確認，
獨立驗證力不足，故降低此方法在最終目標價中的權重，改與DCF並重加權。」
（「這項調整是紅隊複核挑戰4成立後的結果」這句話本身，只寫進「資料完整性
與查證紀錄」章節的紅隊挑戰清單裡，不重複寫進投資論點正文。）
```

**以下用語只能出現在「資料完整性與查證紀錄」章節內**（含其下之紅隊挑戰清單、時效稽核表、結論影響追蹤三個子項）**，不可出現在報告其他任何章節**：「Red Team」「紅隊複核」「紅隊挑戰」「跨模組」「代理人交鋒」「Evidence Curator」「Data Researcher」「Agent 1／2／3」「S1～S7模組」「複核後更新／調整／補充／裁決」。

**2026-09 更新：原本的「結論影響追蹤」例外已取消。** 該子節先前因模板規定其措辭含「跨模組交叉檢驗」而被列為豁免，現已同時改掉模板措辭、並將整個子節移入「資料完整性與查證紀錄」章節（見 s7-synthesis.md Step 2.5 變更說明），因此讀者導向正文不再有任何合法出現上述用語的位置，豁免條款一併移除。

完成修改後，執行 `python3 ~/.claude/skills/equity-research-tw/scripts/validate_equity_report.py --report [路徑]`，確認「正文流程用語洩漏檢查」為 PASS 才算真正做完，不是紅隊清單有附上就結束。
